## 文件说明

- `drae-pet-server`：后端 API 服务，Windows 下文件名以 `.exe` 结尾。
- `drae-pet-frontend`：独立前端服务，将 `/api`、`/healthz` 和 `/ws` 代理到后端。
- `start-server` 与 `start-frontend`：对应平台的启动脚本。
- `CHANGELOG.md`：2.1.0 更新日志与已知限制。
- `VALIDATION.md`：本次构建、测试及启动验证结果。

发布包不包含数据库与预置账号。程序不依赖 Node.js 或 Go 开发环境。

## Windows 启动

1. 将 ZIP 完整解压至可写目录。
2. 双击 `start-server.cmd`，首次启动按提示设置服务端口、管理员用户名与密码；建议端口 `2345`。
3. 双击 `start-frontend.cmd`，浏览器访问 <http://127.0.0.1:5173>。
4. 管理端配置萌卡 NT 节点，再添加或绑定 QQ 账号。

浏览器页面由独立前端提供，前端通过代理连接后端 API。

## Linux 启动

```sh
tar -xzf drae-pet-2.1.0-linux-amd64.tar.gz
cd drae-pet-2.1.0-linux-amd64
sh start-server.sh
# 在另一个终端中进入同一目录
sh start-frontend.sh
```

后端首次启动会提示设置端口及管理员凭据。使用 `sh` 运行启动脚本时，脚本会给对应二进制文件添加执行权限。

## 服务配置

前端默认监听 `127.0.0.1:5173`，代理到 `http://127.0.0.1:2345`。若后端使用其他端口，请在启动前设置 `BACKEND_URL`。服务器部署时可设置 `FRONTEND_HOST=0.0.0.0`，或通过反向代理访问。

| 环境变量 | 作用 |
| --- | --- |
| `BACKEND_URL` | 前端代理的后端地址，默认 `http://127.0.0.1:2345` |
| `FRONTEND_HOST` | 前端监听地址，默认 `127.0.0.1` |
| `FRONTEND_PORT` | 前端端口，默认 `5173` |
| `DATABASE_PATH` | 后端数据库位置，默认 `./data/qq-pet.db` |
| `APP_ADDR` | 空数据库首次初始化时使用的后端监听地址，如 `:2345` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 空数据库首次创建管理员时使用；未设置则终端提示输入 |

启动脚本会将工作目录固定为解压目录，避免把数据库写入其他位置。后续启动读取数据库内已保存的监听地址与账号配置。

## 从旧版升级

1. 停止旧版前后端，备份整个 `data` 目录。
2. 将新版本解压至独立目录，把原服务端实际使用的 `data` 目录复制到新目录。
3. 用启动脚本启动新版后端，数据库迁移会自动执行；随后启动新版前端。
4. 核对账号、宠物与自动控制配置。需要回退时，同时恢复旧程序和升级前备份的数据库。

## 已知限制

Linux x64 二进制通过交叉编译生成，实际 Linux 启动验证情况以 `VALIDATION.md` 为准。
