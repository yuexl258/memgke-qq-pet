# Drae 宠物乐园更新日志

## 2.1.0 · 2026-11-01

### 自动福袋流程

- 自动领取按“查询自家小窝 → 领取自家福袋 → 查询好友小窝 → 领取好友福袋”的顺序执行，自家领取完成后再扫描好友。
- 自家查询或领取失败时记录具体阶段，并继续扫描好友；关闭自动领取后停止后续领取操作。
- 保留每 10 分钟扫描、领取去重、今日领取数量和金币收益统计；重新开启自动领取后可立即发起扫描。
- 自动控制日志区分自家查询、自家领取和好友扫描，便于检查漏查或领取失败。

### 本版包含

- 延续 2.0 系列的 `qqpet_operation` 接口适配、宠物资料与状态展示、好友分页、属性克制 PK 及自动照料功能。
- 包含福袋扫描弹窗、手动领取、自动领取开关，以及按北京时间持久化的每日收益统计。
- 前后端版本统一为 `2.1.0`，提供 Windows x64 和 Linux x64 完整发行包，均内嵌最新网页资源。

## 2.0.1 · 2026-10-30

### 福袋扫描与自动领取

- 修复自家福袋漏查：按照 Android 协议改用 `0x9acb_0`，字段 2 发送字节串 `[14]`，再以 `0x9d70_0` 核验福袋状态。
- 手动与自动扫描均包含自家及好友小窝；扫描结果明确记录自家小窝检查状态。
- 自动控制新增福袋领取开关，开启后每 10 分钟扫描并领取可用福袋。
- 手动与自动领取共享去重账本，按北京时间统计每日福袋数和金币，进程重启后保留。
- 优化福袋扫描弹窗布局，并显示今日领取数、金币收益和扫描状态。

### 验证

- 福袋请求编码、回包解析、自家福袋完整扫描、领取去重、10 分钟调度、跨日统计和配置保存测试通过。
- 前端 15 项测试、生产构建及后端编译通过。
- 已通过在线账号验证自家查询协议；本版未在打包验证中实际领取福袋。
- 部分后端历史协议测试仍失败，详见本版 `VALIDATION.md`。

## 2.0.0 · 2026-10-30

### 萌卡 NT 接口适配

- 宠物常用业务切换至 `qqpet_operation`，覆盖资料、数值、属性、勋章、食物、洗护、活动、好友互动及 PK。
- 同步新版 QQ 账号查询与协议实例选择方式，修复已绑定且在线的账号未出现在宠物小屋的问题。
- 更新原始资料解析及状态展示，调整性别、生日、职业、金币、心情、饥饿、清洁、综合状态及三维属性的数据来源。
- 更新活动选项、学习阶段、活动状态、开始与结算请求，以及食物与洗护用品的库存、购买和使用请求。

### 好友与自动照料

- 好友是否拥有宠物以 Pet ID 为准，修复好友宠物名称和资料缺失问题。
- 修复 `pk.friends` 只读取第一页导致宠物好友最多显示 10 位的问题，支持按游标读取后续页面。
- 修复并完善好友战力查询、PK 发起、状态查询与结算流程，挑战判断计入属性克制，优先选择预计可战胜的好友。
- 调整被雇佣活动的识别与自动召回逻辑，并更新自动喂食、洗护及补货的数据解析。

### 页面与体验

- 优化宠物小屋布局：职业图标随名称展示，宠物 ID 移入基本资料并支持点击复制。
- 恢复小屋动态弹窗，转换互动内容中的文字片段，并展示来访伙伴与互动时间。
- 适配勋章展示；成长日报改为弹窗逐条切换，折线图增加边距及悬浮、点击数值提示。
- 战力榜仅展示前 10 名，前三名增加专属装饰；使用宠物头像，QQ 仅显示前 3 位和后 2 位。
- QQ 账号改为适配桌面和手机的卡片布局，优化详情弹窗，增加离线账号删除入口。

### 福袋接口试验与已知限制

- 增加福袋扫描弹窗及 `send_packet` 查询、领取请求封装，自家地面福袋查询沿用 Android 端的字节串 `[14]` 编码。
- **福袋链路尚未测通，不作为本版已可用功能承诺。** 当前测试节点的好友扫描与自家查询返回 OIDB `236 / cmd not found`；`qqpet_get_coin_bag_detail` 返回 OIDB `135090`。未取得可用福袋列表，尚未验证真实领取成功。
- 部分现有后端测试仍使用旧接口及旧返回字段，完整后端测试套件存在失败；本版附带实际构建、测试和启动验证记录。

### 发布与升级

- 提供 Windows x64 ZIP 与 Linux x64 TAR.GZ，每套均含前端、后端、启动脚本、使用说明与本更新日志。
- 前后端版本统一为 `2.0.0`，独立前端服务内嵌本版网页资源。
- 修复空数据库首次通过环境变量初始化监听地址后，仍因旧查询错误退出的问题。
- 发布包不包含源代码、运行数据库、账号、Token 或会话数据。
- 升级前停止旧程序并备份原服务端的整个 `data` 目录；将该目录放入新版本目录，保留原有运行配置。数据库迁移由新后端启动时执行。
- 由于二开版本过多，采用闭源方式发布，但是允许运营。
