# Drae 宠物乐园 2.6.0

更新日期：2026-11-09 · 升级范围：2.5.2 → 2.6.0

## 官方机器人版本更新推送

- 新增版本更新群通知，可在“推送设置 → 更新推送”中独立开启。
- 开启后每 10 分钟检查一次新版本，使用“系统更新”页面保存的检测节点。
- 发现新版本后向已绑定群聊发送通知，包含当前版本、最新版本、更新说明及下载入口。
- 同一机器人、群聊和版本成功推送后不再重复发送，服务重启后仍保留推送记录。
- 机器人断开、推送关闭或未绑定群聊时暂停检测。
- 页面展示最近检测时间、检测到的版本、最近成功推送时间及失败原因，方便确认推送状态。

## 系统更新节点保存

- 更新节点改为保存到服务端，换浏览器或更换管理设备后可继续使用已保存的配置。
- 系统更新与官方机器人版本推送共用节点设置，支持 GitHub 直连、预设镜像及自定义镜像。
- 新增“保存节点”按钮，可单独保存配置；检查更新时也会保存当前选择。
- 首次升级且服务端尚未保存节点时，可沿用原浏览器中的节点偏好。
- 节点读取失败时显示原因，避免误用其他节点发起检查。

## 好友互动手动重试

- 好友踩一踩新增“重试失败项”按钮，可手动重新尝试今日未成功的好友，无需等待次日。
- 页面显示今日待重试数量、本轮处理进度和已提交数量。
- 手动重试逐一处理失败项；原有每日自动踩一踩仍保持失败后跳过、不自动反复重试的规则。
- 好友 PK 新增“手动重试”按钮，可主动重新检查好友并发起一轮 PK，无需等待每日定时执行时间。
- 自动 PK 处于暂停状态时也可手动执行，操作后保留原有自动开关设置。
- 手动 PK 沿用已保存的好友目录，保留已有执行记录；已有对战优先继续查询和结算。
- 重试进行中显示运行状态并禁止重复提交；切换 QQ 账号后，各账号分别展示自己的执行状态。

## 升级说明

- 从 2.5.2 升级前，建议备份实际使用的数据库及运行配置。
- 手动升级时先停止旧版前后端，再替换配套程序；保留原数据目录、自定义数据库路径和启动配置。
- 按后端、前端的顺序启动，数据库结构由后端启动时自动迁移，随后刷新浏览器。
- 升级后可在“系统更新”中确认并保存更新节点；需要群通知时，先绑定官方机器人群聊，再开启并保存更新推送设置。
- 使用 systemd 或容器托管的服务，继续通过原服务管理方式更新和重启。

由于二开版本过多，所以采用闭源方式发布，但是允许运营。
