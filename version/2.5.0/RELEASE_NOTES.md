# Drae 宠物乐园 2.5.0

更新日期：2026-11-08 · 升级范围：2.4.0 → 2.5.0

## 用户端与手机适配

- 新增用户端页面布局，重新组织首页、账号、宠物、自动照料、好友及钱包等入口，保留 Drae 宠物乐园名称与标志。
- 适配手机侧边导航、底部导航和页面布局，优化小屏幕下的信息展示与操作。
- 管理端新增“用户端外观”设置，可切换新版或原版布局，并调整主题色、侧栏、页面密度、圆角、字号、内容宽度及欢迎语；普通用户不可修改。
- 管理端原有布局保持不变，用户端外观设置不会影响管理端。
- 修复原版前端手机端选择照料好友时弹窗受容器遮挡、内容显示不全的问题；好友列表支持独立滚动，分页和保存按钮保持可见。
- 优化好友选择项的长昵称换行，避免昵称挤出选择标记。

## 好友列表与每日任务

- 自动踩一踩及好友 PK 使用数据库中已保存的好友数据，移除 PK 前额外访问 `pk.friends` 的步骤。
- 除主动更新好友目录外，页面读取和自动任务不再重复请求框架好友列表，减少重复请求与等待。
- 好友踩一踩调整为每天北京时间 **00:00** 开始执行。
- 每位好友每天仅自动尝试一次踩一踩，失败或超时后直接跳过，当天不再重试，服务重启后也不会重复补发。
- 好友 PK 调整为每天北京时间 **01:00** 开始执行，最多 10 次。
- PK 后不再额外触发喂食或洗护，日常照料按自身设置独立运行。

## 指令调度与页面响应

- 自动任务发送至框架的业务指令统一经过节点队列，按顺序执行，并控制指令间隔，减少同一时间集中请求导致的超时。
- 排队中的指令支持取消；节点断开后终止待执行请求，恢复连接时不重放旧队列。
- 网页手动操作直接提交框架，无需等待自动任务队列。
- 优化库存及账号在线状态的并发查询，合并重复的运行状态和活动选项请求。
- 修复好友刷新状态轮询重叠的问题，避免慢请求积压。
- 自动照料页面先展示数据库中的任务状态，再独立加载实时活动信息，减少页面等待。
- 页面按需加载，减少首次访问需要下载的脚本体积。

## 福袋分批扫描与领取

- 自动福袋改为每扫描 **10 位好友**就领取当前批次发现的福袋，领取完成后继续下一批，直到好友扫描完成。
- 单个好友资料查询、福袋核验或领取失败时记录原因并跳过，继续处理其他好友。
- 调整大好友列表的扫描超时控制，保留单次请求时限及分页异常检测，避免整轮扫描因耗时较长被提前中断。
- 网页手动扫描逐批显示结果，已发现的福袋可立即领取，无需等待全部好友扫描结束。
- 后续扫描失败时保留已显示的结果；关闭扫描弹窗或离开页面会取消本次手动扫描。
- 已确认的领取记录及每日数量、金币统计继续保存。

## 自动照料与召回修复

- 修复被对方删除好友、好友目录缺失或宠物资料失效后，无法从自动照料名单移除的问题。
- 失效好友保留在照料名单中并显示原因，可单独移除；移除仅修改本地名单，不依赖框架在线或其他好友资料有效。
- 保存照料设置时仅校验新增好友，避免已有失效好友阻止其他设置保存。
- 自动照料跳过缺少有效宠物资料的目标，继续处理其他可照料好友。
- 修复被雇佣召回后仍使用旧活动 ID 请求结算、触发 OIDB `135004` 的问题。
- 召回后按实际活动状态处理：仍在活动中则等待返回；已完成且尚未空闲时请求结算；确认空闲后直接继续计划，保留正常收益结算流程。

## 日志与稳定性

- 自动控制及好友 PK 执行日志仅保留北京时间当日记录，服务启动时和每天 **00:00** 自动清理历史执行日志。
- 账号、好友、照料名单、任务配置及状态、福袋领取和收益数据继续保存。
- 更新旧协议测试与返回字段，修复自动控制、自动 PK 和框架适配中的测试问题，后端全量测试恢复通过。
- 本轮前端 32 项测试、生产构建及独立前端 Go 测试通过；好友选择弹窗已验证手机横竖屏、桌面端和新版布局。

## 升级方式

停止旧版前后端，备份整个 `data` 目录，再将新版程序与配套前端资源替换到位后启动。保留原有数据目录，数据库迁移由后端启动时执行。

升级后历史执行日志会按当日保留规则自动清理，需要留存历史日志时请在升级前备份。浏览器仍显示旧页面时，可刷新页面缓存。

由于二开版本过多，所以采用闭源方式发布，但是允许运营。
