## 功能介绍

### 宠物小屋

- 查看宠物资料、职业、心情、饱食度、清洁度、金币、属性和战力，收集并查看勋章。
- 手动喂食、洗护，安排学习、打工和冒险；打工支持普通、随机雇佣和指定好友雇佣。
- 查看成长日报、互动记录和战力排行榜，记录伙伴的成长。

### 好友互动与福袋

- 刷新好友列表，查看好友宠物资料、拜访小窝和踩一踩，也能向好友发起 PK。
- 扫描自家及好友小窝的福袋并领取，查看领取数量与金币统计。
- 自动福袋按每 10 位好友一批核验并领取，领取完再扫描下一批，直至全部完成；单个好友查询或领取失败会记录并跳过。网页手动扫描逐批显示结果，可边扫描边领取，关闭弹窗会停止本次手动扫描。

### 自动照料

- 分别开启日常照料、每日活动计划、被雇佣自动召回、福袋领取、好友踩一踩和自动 PK，并查看各模块执行记录。
- 为自己及选定的好友设置照料阈值；饼干或香皂片不足时自动购买。
- 照料名单中的失效好友仍可查看和单独移除；移除仅更新本地照料名单，不依赖好友关系、框架在线状态或其他好友资料。
- 每日活动可安排学习、打工和冒险；连接恢复后可继续因掉线暂停的功能。
- 被雇佣召回后按活动状态处理收益：仍在活动中等待返回，已完成且未空闲时才请求结算；确认空闲后直接继续计划，不再结算旧活动 ID。
- 好友踩一踩每天北京时间 00:00 开始，从数据库中保存的好友逐一执行；每位好友每天仅自动尝试一次，失败或超时直接跳过，当天不再重试，服务重启也不补发；好友列表只在主动更新时请求框架。
- 好友 PK 每天北京时间 01:00 开始，最多 10 次，PK 后不触发喂食或洗护，日常照料独立执行。
- 自动任务执行日志仅显示当日记录，服务启动时及每天北京时间 00:00 自动删除之前的执行日志；账号、好友、任务配置和状态、福袋收益数据继续保存。

### 账号与乐园管理

- 注册、登录和管理多个 QQ 账号，生成并管理专属设备指纹。
- 查看钱包、乐园公告及个人资料；管理端支持成员、QQ 账号、服务套餐、卡密、公告和节点配置。
- 支持配置 QQ 官方机器人，通过绑定码关联账号和群，使用签到及金币查询功能。

## 解压后的文件

- `drae-pet-server.exe` / `drae-pet-server`：后端服务，保存账号、配置和数据库。
- `drae-pet-frontend.exe` / `drae-pet-frontend`：内嵌网页的前端服务，将 `/api`、`/healthz` 和 `/ws` 转发给后端。
- `start-server.cmd` / `start-server.sh`：启动后端。
- `start-frontend.cmd` / `start-frontend.sh`：启动前端。
- `SHA256SUMS.txt`：解压目录内文件的校验值；Release 页面另附两个压缩包的校验值。

两个服务都要运行，且应从**解压后的文件夹**启动；不要在压缩包预览窗口里直接运行。程序不需要安装 Node.js 或 Go。首次启动会在解压目录创建 `data/qq-pet.db`，请将文件夹放在有写入权限的位置。

## Windows：首次运行

1. 下载 Windows ZIP，右键“全部解压”。打开解压后含有 `start-server.cmd` 的文件夹。
2. 双击 `start-server.cmd`。首次运行依次输入服务端口号、管理员用户名、管理员密码；端口建议填 **2345**。看到 `server started` 后保留这个窗口。
3. 双击 `start-frontend.cmd`，保留第二个窗口。看到“Frontend 2.5.1 已启动”后，在浏览器打开 <http://127.0.0.1:5173>。
4. 用刚设置的管理员账号登录。先在管理后台配置正在运行的萌卡 NT 节点，再让用户生成专属指纹并添加 QQ。

每次重启都按“后端 → 前端”的顺序运行两个脚本。后端使用已有数据库时会读取已保存的端口和管理员账号，不再重复初始化。要停止服务，可在两个命令窗口分别按 `Ctrl+C`。

## Linux：首次运行

在存放压缩包的目录执行：

```sh
tar -xzf drae-pet-2.5.1-linux-amd64.tar.gz
cd drae-pet-2.5.1-linux-amd64
./start-server.sh
```

首次运行依次输入端口号（建议 **2345**）、管理员用户名、管理员密码。看到 `server started` 后，保持这个终端运行；在**另一个终端**进入同一解压目录并启动前端：

```sh
cd drae-pet-2.5.1-linux-amd64
./start-frontend.sh
```

在服务器本机打开 <http://127.0.0.1:5173>，登录后到管理后台配置萌卡 NT 节点。启动脚本及二进制在压缩包内已设置执行权限；如果解压方式丢失权限，可运行 `chmod +x start-server.sh start-frontend.sh drae-pet-server drae-pet-frontend`。用 `Ctrl+C` 停止对应服务。

Linux 解压版支持在管理后台下载并安装更新，两个服务应由同一用户使用启动脚本或 `nohup` 运行。更新助手会保留后端原工作目录及前端的 `BACKEND_URL`、`FRONTEND_HOST`、`FRONTEND_PORT` 和 `NO_OPEN`，停止前后端后替换程序，再按后端、前端的顺序启动；退出等待超过 30 秒会取消安装。安装提交后页面会等待新版本恢复并自动刷新，超过 3 分钟未确认时会提示检查更新日志。`systemd` 托管和容器主进程应使用手动更新，由原服务管理器重新启动。

更新过程记录在安装目录的 `.drae-update.log`，重启输出分别写入 `drae-pet-server.log` 和 `drae-pet-frontend.log`。新程序启动后立即退出时会恢复旧程序，失败暂存目录中的 `previous-*` 备份会保留；再次安装会使用新的暂存目录，不覆盖旧备份。下载中断后仍可断点续传。更新不会替换账号数据库。若助手被强行终止，确认没有更新进程后，可用 `rmdir .drae-update.lock` 清除残留锁再重试。

## 服务配置

前端默认监听 `127.0.0.1:5173`，代理至 `http://127.0.0.1:2345`。首次启动后端时若选择了其他端口，例如 `8080`，需要在启动前端的**同一个终端**设置 `BACKEND_URL`：

在解压目录的地址栏输入 `cmd` 打开命令提示符，再执行：

```bat
set BACKEND_URL=http://127.0.0.1:8080
start-frontend.cmd
```

Linux 对应命令：`BACKEND_URL=http://127.0.0.1:8080 ./start-frontend.sh`。远程访问时，将 `FRONTEND_HOST` 设为 `0.0.0.0`，浏览器访问 `http://服务器IP:5173`，并放通前端端口；也可以通过反向代理访问。

| 环境变量 | 作用 |
| --- | --- |
| `BACKEND_URL` | 后端地址，默认 `http://127.0.0.1:2345` |
| `FRONTEND_HOST` | 前端监听地址，默认 `127.0.0.1` |
| `FRONTEND_PORT` | 前端端口，默认 `5173` |
| `NO_OPEN` | 设为 `0` 时尝试自动打开浏览器 |
| `DATABASE_PATH` | 数据库位置，默认 `./data/qq-pet.db` |
| `APP_ADDR` | 空数据库首次初始化的后端地址，如 `:2345` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 首次创建管理员使用，未设置则终端提示输入 |
| `MOKANT_COMMAND_INTERVAL_MS` | 框架节点串行指令间隔，默认 `200` 毫秒 |
| `MOKANT_COMMAND_TIMEOUT_SECONDS` | 单条框架指令发出后的等待上限，默认 `20` 秒 |
| `MOKANT_COMMAND_QUEUE_SIZE` | 每个框架节点最多排队的指令数，默认 `256` |

启动脚本将工作目录固定在解压目录。后续启动读取数据库内保存的监听地址和账号配置。

后台自动任务的框架业务指令按节点先进先出排队，每个节点同时只执行一条自动指令。网页操作（包括账号管理、查询、宠物操作、底层发包，以及用户主动触发的好友刷新和照料刷新）直接提交，不等待自动任务队列；独立请求通过各自的指令 ID 接收回复。网页单条指令仍受调用方截止时间和 `MOKANT_COMMAND_TIMEOUT_SECONDS` 限制。自动任务排队时间受调用方的截止时间约束，已取消的待执行指令会跳过；已发送的自动指令等待回复或单条超时后再执行下一条。队列满时返回忙碌错误，断线时清理该连接的待执行指令，重连后不自动补发。认证和心跳独立发送，以维持连接。

## 用户端外观

用户端默认使用清爽工作台布局，保留 Drae宠物乐园名称和标志。首页汇总账号、金币、自动照料与运行记录，手机端提供底部快捷导航及侧栏抽屉。

管理员可在 **管理后台 → 系统设置 → 用户端外观** 中修改布局、主题颜色、侧栏颜色、页面间距、圆角、基础字号、内容宽度和首页欢迎语。清爽工作台与经典乐园均支持上述配置，共用同一套设置；经典乐园保留原有导航和 Drae 名称、标志，登录页、手机导航和弹窗也会跟随主题。编辑时可实时预览，欢迎语留空时不显示。保存后配置写入数据库，对所有用户生效；已打开的用户页在刷新或重新获得窗口焦点时读取新配置。普通用户无法修改外观。管理后台继续使用原有布局与样式。

开发时可通过 `BACKEND_URL` 指定 Vite 代理的后端地址，默认仍为 `http://127.0.0.1:2345`。

## 从旧版升级

从 2.5.0 或更早版本升级到本版时，建议手动替换前后端程序一次；旧程序内置的更新助手不包含本次修复，不能依靠新版安装包修复尚在运行的旧助手。保留实际使用的数据库路径和启动环境。

1. 停止旧版前后端，备份整个 `data` 目录。
2. 将新版本解压到独立目录，把原服务端实际使用的 `data` 目录复制到新目录。
3. 启动新版后端，数据库迁移自动执行；随后启动新版前端并刷新浏览器。
4. 核对自动控制开关、每日计划和照料设置。选择打工雇佣方式或修改每日计划后，点击保存计划。
5. 原来使用共享指纹的 QQ，再次登录前先生成自己的专属指纹，下线后通过“修改账号”选择指纹并完整填写配置。已在线账号不会自动更换指纹。

需要回退时同时恢复旧程序和升级前备份的数据库。
